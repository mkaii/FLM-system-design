Phases 6–7 — Concurrency

Concurrency & Locking

The one guarantee the whole project exists to prove: 100 threads try to book the same seat for the same show, and exactly one succeeds. That guarantee comes from three structures that must stay separate, plus a lock taken per seat — never one lock for the whole system.

This all holds for one JVM. The lock is an in-memory ReentrantLock, so it says nothing about a second instance of this service running elsewhere. The spec is explicit that multi-JVM correctness — database-level constraints, pessimistic/optimistic locking at the DB, or a distributed lock via Redis — is a deliberately future concern, not something this phase implements. Building it now would be solving a problem the current architecture (single JVM, in-memory repositories) doesn't actually have yet.
